# Исправление сброса прокрутки — 5 ноября 2026
Причина подтверждена до изменения: за 10 небольших wheel-импульсов обёртка ScrollTrigger.refresh зарегистрировала 359 вызовов. Стек указывал на rAF callback в site-motion: MutationObserver вызывал refresh, refresh менял DOM pin/pin-spacer и порождал следующую MutationObserver-итерацию. ResizeObserver main/details добавляли повторные пересчёты. Прямых window.scrollTo(0,0) или lenis.scrollTo(0) в приложении нет; scroll.current.scrollTo(0,0) касается только внутреннего просмотрщика альбомов и сохранён.
Исправление: наблюдатель DOM только обнаруживает элементы для прежних reveal-анимаций; refresh из MutationObserver/ResizeObserver удалён. Два источника startup refresh: Promise.all(fonts.ready + load/decode только img/build и img/rooms), однократный window load. Если пользователь уже прокручивает — запрос откладывается до scrollEnd. Индивидуальные load картинки только разрешают Promise, не вызывают refresh. Автоматический refresh оставлен только для реального resize; ignoreMobileResize:true. После любого refresh обработчик вызывает lenis.resize на desktop, с cleanup.
Таймлайн, кадры, camera, pin, scrub/snap, геометрия и визуальные анимации не изменялись.
Проверки Chrome headless: полная страница от начала до конца на 1440×1000 wheel slow134/fast49 импульсов, touch390×844 slow102/fast58 свайпов через CDP touchStart/touchMove/touchEnd. В каждом проходе наблюдались все stages0…13, включая все6комнат; refresh во время проходов0; прыжков из y>900 в y<200 нет, нет overflow/pageerror. Данные after.json. Эмуляция физического телефона не заменяет.
Дополнительно мобильная высота844→790: scrollY3500 сохранён, refresh0. Desktop явный refresh вызывает lenis.resize ровно1 раз. Данные resize.json. Build и 5 существующих тестов успешны.
