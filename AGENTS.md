# AGENTS.md — Kerbez Aru, объединённый сайт

## Публикация и структура
- `index.html` в корне — готовая статическая страница с пререндеренным контентом. Публиковать корень репозитория, сборка на хостинге не обязательна.
- `assets/` — фотографии, альбомы, локальные шрифты, скомпилированные CSS и JS.
- `img/build/` — неизменённые кадры 1344×752 варианта 3.
- `vendor/` — исходные GSAP 3.13, ScrollTrigger, SplitText, Lenis 1.1.13.
- `source/index.html`, `source/src/` — редактируемая React-основа текущего сайта и интегрированная сцена.
- `scripts/build.mjs` — Vite-сборка и пререндер через ReactDOMServer; результат переносится в корень.
- `archive/variant-2/` — полная копия исходного варианта 2 до объединения; `SHA256.json` подтверждает целостность. Не менять архив.
- `qa/` — снимки и отчёт проверки; HTML-фикстуры не публиковать отдельно.

## Работа
После `npm ci` команда `npm run build` обновляет корневой index.html и бандлы. `npm test` проверяет локальные ссылки, альбомы, архив и наличие контента без JS. Для просмотра: `python -m http.server 4174` из корня.
Не править сгенерированный index.html вручную: менять source/src и пересобирать. Не добавлять абсолютные пути диска или ссылки file://. Все локальные картинки, скрипты и шрифты должны работать при публикации в подпапке.

## Сцена #build
Сразу после #home, перед направлениями студии и школы.
- `build-markup.json` хранит исходную сцену с 69 SVG path и 14 этапами (8 сборки + 6 комнат).
- `build-motion.js` сохраняет гомографию SRC/FLAT/QUAD, matrix3d, рисование, кадры, метки p0…p7 (включая p3a), scrub, pin и snap по labels. После p7: нырок и метки r0…r5; камера shot()/C() меняет масштаб и фокус, MOB ослабляет приближения на телефонах. Дневные кадры 3–6 гасятся на этапе света.
- Фон: #E2E0D7, при свете #7B6757. Текст и кнопки согласованы с зелёно-кремовой системой сайта.
- `BuildExperience` мемоизирован: прокрутка шапки не должна заменять DOM, которым управляет GSAP.
- Инициализация после загрузки локальных шрифтов. gsap.context и matchMedia очищают стили и события при переключении reduced motion.
- При prefers-reduced-motion: reduce сцена статична, нет Lenis/pin. Без JS весь HTML уже виден, показываются финальный дневной кадр и описания.
- Сохранять подпись «Концепт-визуализация»; не выдавать эту сцену за реализованный объект.
- Менять кадры только с сохранением геометрии; иначе пересчитать QUAD.

## Анимации остального сайта
`source/src/site-motion.js` + `motion.css`: заголовки и карточки появляются через IntersectionObserver, линии разделов прорисовываются, фото hero/встречи/портрета имеют слабый desktop-параллакс. Есть индикатор чтения и текущий раздел меню. Секция #build исключена из общих анимаций. Не добавлять дополнительные pin-секции.
Статичный CSS по умолчанию показывает весь контент. gsap.matchMedia отключает движение при reduced-motion и очищает стили на смене breakpoint. Раскрываемые блоки отслеживаются после открытия, фокус сразу показывает ожидающий элемент. После изменения высоты контента ScrollTrigger.refresh запланирован через rAF.
Кнопки этапов #build обрабатываются делегированием на секции, чтобы не зависеть от обновления дочерних узлов. Начальная прозрачность сетки задана явно для корректного обратного прохода.

## Авторский разбор и связь студии со школой
`SignatureSections.jsx` и `signature.css`: три открытых превью ведут в существующие альбомы/фотогалерею; полный список по-прежнему закрыт в details. Разбор Алматы основан на листе планировки, без вымышленных пожеланий заказчика, бюджета и сроков. Обложка Алматы — страница 8.
`DesignNotes` — отдельный React-компонент с native dialog; делегированный триггер в гостиной концептуальной сцены не заменяет DOM GSAP. Сохранять подпись концепта и восстановление фокуса.
`StudioSchoolBridge` связывает проектные задачи и учебную программу. `TemplateWorkflow` показывает схему работы и реальный учебный лист, не выдаёт его за интерфейс шаблона или живую Revit-демонстрацию.
При программном переходе Lenis временно отключает притягивание snap; при ручной прокрутке привязка остаётся ко всем меткам исходной сцены. Начальное состояние кадров задаётся явно для переинициализации при смене breakpoint.
